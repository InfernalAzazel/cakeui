# Vue Notes

A complete CakeUI app in one Python module and one Vue component. It is the
example to read right after the quickstart: small enough to finish in one
sitting, real enough to show the parts that matter.

```bash
cd examples/vue-notes
uv sync
npm --prefix web install
uv run cakeui dev
```

A window opens on the Vite dev server. Notes are written to a JSON file in your
user-data directory, so they survive a restart:

| Platform | File |
|---|---|
| macOS | `~/Library/Application Support/vue-notes/notes.json` |
| Windows | `%APPDATA%\vue-notes\notes.json` |
| Linux | `$XDG_DATA_HOME/vue-notes/notes.json` (or `~/.local/share`) |

## What to look at

| File | The idea it demonstrates |
|---|---|
| `main.py` | Pydantic models as arguments and return values, commands, events, `window` injection |
| `web/src/App.vue` | `invoke`, `emit`, `listen`, and one place where errors are caught |
| `web/src/lib/cakeui/cakeui-boot.ts` | The only CakeUI-specific frontend module; editable |
| `web/src/lib/cakeui/cakeui.js` | Generated by the CLI, never edited by hand |

## Models, not dictionaries

`Note` is declared once and then used everywhere: it is what the JSON file holds,
what every command returns, and what `save_note` accepts.

```python
class Note(BaseModel):
    id: int
    text: str
    done: bool = False
    created_at: datetime
```

That single class buys three things:

- **Arguments are validated before the body runs.** `save_note(note: Note)` gets a
  real `Note` instance, and `{"id": "not-an-int"}` is refused with
  `code: "validation_error"` plus the offending field.
- **Return values are checked too.** `-> list[Note]` means a command cannot drift
  away from the shape the frontend expects; a mismatch is an error, not a broken
  render.
- **Types cross the bridge by themselves.** `created_at` is a `datetime`: Pydantic
  parses the ISO string the frontend sends back, and the bridge serialises it to
  that same string on the way out.

Plain builtins sit next to models without ceremony: `add_note(text: str)`,
`delete_note(note_id: int, window: Window)`, `crash(kind: str = "boom")`. Lists,
dicts, `Literal`, `Optional`, `Path`, `UUID`, enums and dataclasses work the same
way.

Event handlers take models too:

```python
class LogLine(BaseModel):
    message: str

@app.on("log")
def on_log(line: LogLine) -> None:
    print(line.message)
```

Writes go through one helper, so saving and notifying happen together:

```python
def _write(notes: list[Note]) -> list[Note]:
    """Persist and broadcast in one step, so no command can forget half of it."""
    STATE.parent.mkdir(parents=True, exist_ok=True)
    payload = [note.model_dump(mode="json") for note in notes]
    STATE.write_text(json.dumps(payload, ensure_ascii=False, indent=2) + "\n", "utf-8")
    app.emit("notes:changed", {"count": len(notes)})
    return notes
```

That is why two windows stay in sync. `delete_note` shows the other half: it
answers with `window.emit` instead of `app.emit`, so the confirmation toast only
appears in the window you clicked in.

## Try the errors

The app has a **Break something** button that calls a command which raises on
purpose, and the composer refuses notes shorter than 1 or longer than 140
characters. Both end up in the same banner, because both arrive as a
`CakeUIError` with a stable `code`:

| What you did | `code` |
|---|---|
| Submitted an empty or over-long note | `invalid_note` |
| Sent a note whose fields do not fit the model | `validation_error` |
| Acted on a note that had already been deleted elsewhere | `note_not_found` |
| Pressed **Break something** | `internal_error` |

Click **Log to Python** to send an event the other way; `on_log` prints it in the
terminal that is running the app.

## Build it

```bash
uv run cakeui build
```

On macOS this produces `dist/main.app`. The icon in `assets/` is the CakeUI
default; replace the files and keep the names to make it yours.

## Back in a plain browser

`npm --prefix web run dev` works too. The frontend then has no Python behind it:
`cakeui-boot.ts` notices that `window.pywebview` never appeared and logs it,
while every `invoke` rejects. Useful for styling work.

After upgrading `cakeui` or `cakeui-cli`, refresh the generated files:

```bash
uv run cakeui sync
```
