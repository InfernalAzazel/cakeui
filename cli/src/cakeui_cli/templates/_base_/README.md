# {{display_name}}

A CakeUI desktop app: a Vite frontend you already know, plus a Python backend
instead of Node.

## Run it

```bash
uv sync
{{install_command}}
cakeui dev
```

`cakeui dev` runs the web frontend's own `dev` script with {{package_manager}},
reads the URL Vite prints, and opens the window on it. Hot reload works exactly as
it does in the browser. When the window closes, the dev server is stopped.

Already have a dev server running? `cakeui dev --url http://localhost:5173`.

## Layout

```
main.py                 Python: commands (@app.command), events (@app.on)
pyproject.toml          [tool.cakeui]: entry point, web paths, build settings
assets/                 the app icon, one file per platform
web/                    the Vite project, generated by `{{package_manager}} create vite`
  src/lib/cakeui/       CakeUI's own files live here, not mixed into src/
    cakeui-boot.ts      generated glue (imports the bridge, shows toasts)
    cakeui.js           generated ESM bridge (do not edit)
    cakeui.d.ts         generated types for the bridge
```

`main.ts` (or `main.js`) ends with one line that imports `./lib/cakeui/cakeui-boot`.
Delete it to detach CakeUI and use the frontend as an ordinary web app.

## The icon

`assets/` holds the same picture in the three formats the platforms want:

| File | Used by |
|---|---|
| `assets/icon.icns` | the macOS `.app` bundle |
| `assets/icon.ico` | the Windows `.exe` and its window |
| `assets/icon.png` | Linux, and the window icon while you run `cakeui dev` |
| `assets/icon.svg` | the editable source, not shipped in the build |

To use your own, replace the files but keep the names. `icon = "assets/icon"` in
`pyproject.toml` names the group, not one file: on each platform CakeUI picks the
first format that exists, falling back to `icon.png`. Drop in only a
1024x1024 `icon.png` and everything still works, including macOS, where Nuitka
converts it to `.icns` for you.

Changing the folder or the base name? Point `icon` at the new stem
(`icon = "branding/logo"`) or at a directory holding `icon.*`
(`icon = "branding"`). A full filename also works, but then every platform gets
that one file.

`cakeui info` prints which file this machine would pick. `cakeui build` copies
the icon into the artifact, so the packaged app finds it at runtime without extra
`include_data_dir` entries.

## Calling Python from the frontend

```ts
import { invoke } from "./lib/cakeui/cakeui.js";

const { message } = await invoke<{ message: string }>("greet", {
  name: "Ada",
  excited: true,
});
```

The matching Python side:

```python
@app.command
def greet(name: str, excited: bool = False) -> dict[str, str]:
    return {"message": f"Hello, {name}!"}
```

Arguments are validated before the body runs. A bad call rejects with a
`CakeUIError` whose `code` is `"validation_error"` and whose `details` lists the
offending fields.

## Events

| Direction | Python | TypeScript |
|---|---|---|
| Python → JS | `app.emit("toast", {...})` / `window.emit(...)` | `listen("toast", fn)` |
| JS → Python | `@app.on("log")` | `emit("log", {...})` |

`src/lib/cakeui/cakeui-boot.ts` already listens for `toast` and renders it, and
does one `invoke("notify", ...)` round trip at startup so you can see the bridge
working.

Everything in `src/lib/cakeui/` is generated by the CLI. After upgrading
`cakeui` / `cakeui-cli`, refresh it to the installed version:

```bash
cakeui sync             # rewrite the bridge, the types and cakeui-boot.ts
cakeui sync --dry-run   # only show what would change
cakeui sync --force     # also overwrite your own edits to cakeui-boot.ts
```

`cakeui.js` and `cakeui.d.ts` are build output, so they are always overwritten.
`cakeui-boot.ts` is meant to be edited, so a modified copy is left alone unless
you pass `--force`.

## Building

```bash
{{build_command}}   # writes web/dist
cakeui build       # build the frontend, then package with Nuitka
```

`cakeui build` runs the `build` script from `web/package.json`, then compiles
`main.py` with [Nuitka](https://nuitka.net/) into a self-contained app:

- macOS: `dist/main.app` (a bundle; pyobjc only works inside one, so this is
  not optional). Needs Nuitka 4 or newer.
- Windows / Linux: `dist/main.dist/` for `mode = "standalone"`, or a single
  executable for `mode = "onefile"`.

Useful flags: `--dry-run` prints the exact Nuitka command, `--no-web` reuses the
existing `web/dist`, `--mode` and `--output-dir` override the config. Everything
in `[tool.cakeui.build]` is passed through, so per-platform quirks go in
`extra_args`.
